# 数据分析教程：从一个转化率问题到 25 个分析模型

这是**平台使用者**（分析师/运营/产品）的教程：系统已部署、SDK 已接入、事件已进仓（前置见
[上手教程](tutorial.md)），本篇回答"**然后呢**"——用真实后台功能回答一个具体业务问题，
并带你把 25 个分析模型各归其位。

> 行文以**任务意图 + 菜单路径**为准（菜单名以当前 main 后台 i18n 为准，不绑定控件坐标）。
> 全程演示用 [demo-data.sql](../backend/sql/postgresql/demo-data.sql) 的电商数据：
> 已内置 `app_launch / view_home / view_product / add_to_cart / submit_order / pay_success / click`
> 七个事件 Schema 与风险规则，导入后即可跟做。

## 0. 主线问题

> **"从浏览商品到支付成功，转化率是多少？流失在哪一步？哪些用户流失了？"**

这是漏斗分析的标准问题，但我们会走完整链路：先确认数据在 → 建漏斗 → 看流失 → 下钻单用户 → 固化成看板。

## 一、确认数据已可查（事件趋势）

菜单：**数据分析 → 基础分析 → 事件趋势**（`/data-analysis/event-trend`）

1. 选应用（appId）+ 事件（如 `view_product`）+ 时间范围；
2. 能看到趋势曲线 = 数据已入仓且可查。查不到回到[上手教程 §四](tutorial.md#四验证数据链路kafka--doris--看板)检查入仓链路；
3. 同一页面可按维度拆分（渠道/平台等）——回答"哪个渠道注册量最高"这类问题。

> 事件名下拉可选范围 = 「数据配置 → 应用管理」关联应用 + 「事件 Schema」登记的事件。
> Schema 登记（事件名/属性/必填）见 [接入指南 §十六](sdk_integration.md)，是上报校验的源头。

## 二、漏斗分析（主线模型）

菜单：**数据分析 → 基础分析 → 漏斗分析**（`/data-analysis/funnel`）

用 demo 数据搭一个 4 步电商漏斗：

```
view_product（浏览商品）→ add_to_cart（加购）→ submit_order（提交订单）→ pay_success（支付成功）
```

读结果的姿势：

- **整体转化率**与**每步流失率**——第几步掉人最多，就是优化优先级；
- 转化窗口（如 1 天内完成）决定了口径：窗口太长会把"几天后回来支付"也算转化，太短会漏掉犹豫用户；
- 对比维度（渠道/平台/新老用户）可以横向看哪组人漏得最狠。

**流失了怎么办？** 两个下钻入口：

## 三、行为序列 + 用户 360（单用户下钻）

- **数据分析 → 基础分析 → 行为序列**（`/data-analysis/behavior-sequence`）：
  查看流失用户的逐条行为记录——"加购后没下单的用户，最后做了什么？"是去比价、去改地址，还是直接退出？
- **用户洞察 → 用户 360**（`/user-360`）：
  按设备 ID / 用户 ID 聚合一个用户的完整画像：属性、标签、事件流水、会话。
  单用户客服/运营场景直接用这个页面。

配合 **会话回放**（`/insight/replays`，Web SDK 会话回放开启时）可以直接回放流失用户的操作过程。

## 四、留存分析（第二个高频模型）

菜单：**数据分析 → 基础分析 → 留存分析**（`/data-analysis/retention`）

标准玩法：以 `app_launch`（或注册）为初始行为，看 D1/D7/D30 留存。

- 初始行为 + 回访行为 + 时间粒度（日/周）三要素定口径；
- 新老用户口径差异看 **深度洞察 → 新老用户对比**（`/new-vs-old`）；
- 大盘用户结构是否健康看 **深度洞察 → 生命周期**（`/lifecycle`）——DAU 没跌但新客占比在掉，就是预警。

## 五、点击热力图（需要 SDK 自动埋点配合）

菜单：**数据分析 → 基础分析 → 点击热力图**（`/data-analysis/click`）

- 数据来源是 SDK 自动埋点的 `click` 事件（Web SDK 自动采集 `clickX/clickY/elementXpath/pageUrl`）；
- 按页面聚合看点击分布，回答"哪个元素被高频点击/哪个按钮没人点"；
- 移动端无 DOM 坐标，热力图主要面向 Web 端（见 [接入指南 §三](sdk_integration.md#三平台采集差异)）。

## 六、25 个模型各归其位（速查表）

三大类模型在菜单里分三组（**数据分析** 下：基础分析 / 深度洞察 / 游戏专项）。逐个"什么问题用什么模型"：

**基础分析**（日常 80% 的问题在这里）：

| 菜单项 | 回答什么问题 |
|---|---|
| 事件趋势 | 某事件的量与趋势；按维度拆分对比 |
| 漏斗分析 | 多步转化与流失（本篇主线） |
| 留存分析 | D1/D7/D30 留存 |
| 维度对比 | 两个时间段/两个维度的指标对比 |
| 归因分析 | 哪个触点促成了转化 |
| 分布分析 | 单用户频次分布（复购率、使用深度） |
| 行为序列 | 单用户逐条行为记录（验证流失原因） |
| 用户分群 | 满足条件的用户都有谁（也可从「增长运营 → 用户分群」进入做圈人） |
| 点击热力图 | 页面元素点击分布 |
| 转化路径 | Sankey 图看群体最常见路径与最短转化路径 |
| 实时大屏 | 当日实时大盘（投屏用） |

**深度洞察**：

| 菜单项 | 回答什么问题 |
|---|---|
| 生命周期 | 用户结构健康度（新客/活跃/沉默占比） |
| 流失与回流 | 在哪流失、什么行为能拉回来 |
| 间隔时间 | 注册→首付多久；两次购买隔几天 |
| 矩阵分析 | 功能四象限（核心/边缘，该优化还是下线） |
| 付费分析 | ARPU / ARPPU / 付费率 / GMV |
| 会话分析 | 会话时长分位、跳出率、会话深度 |
| 异常检测 | 哪些事件 PV 暴涨暴跌（埋点丢失预警） |
| 新老用户对比 | 新老用户行为与付费差异 |

**游戏专项**（serverId / level 维度是 SDK 游戏字段，见 [TrackOptions](../sdk/flutter/uba/README.md)）：

| 菜单项 | 回答什么问题 |
|---|---|
| 关卡分析 | 哪关卡人最多、数值平衡 |
| 付费分层 | 大 R 贡献占比（二八定律验证） |
| LTV 生命周期价值 | 第 7/30/90 天累计价值、渠道 LTV 对比 |
| 滚服留存 | 各区服 D1/D3/D7 留存 |
| 在线统计 | PCU / ACU |
| 经济系统 | 金币/钻石产出消耗平衡、刷币迹象 |

> 全部模型的"典型问题"完整版见 [README 分析模型](../README.md#分析模型)；字段口径与协议见 [接入指南](sdk_integration.md)。

## 七、固化成果：看板

菜单：**增长运营 → 自定义看板**（`/custom-dashboards`）

## 八、坑与提示

- **查不到数据先查链路**：事件趋势都查不到时，问题在采集/入仓不在分析（回[上手教程](tutorial.md) §四）；
- **口径先行**：漏斗窗口、留存粒度、新老定义没对齐，跨团队数字就会打架——先在团队内统一；
- **分析模型是双端核心**：想新增模型或改口径属于二次开发（分析聚合在 OLAP 侧），见 [二次开发导引](development_guide.md) 场景 C；
- 当天数据可见性：跑 `uba-ingest etl --loop --every 1h` 做日内刷新（见[上手教程](tutorial.md)）。
